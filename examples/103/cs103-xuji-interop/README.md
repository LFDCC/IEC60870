# 许继 103 over 104 全操作验收工具

用库内的许继私有实现，逐项执行许继 103 模拟器包含的全部操作，校验应答并记录收发报文。

## 用法

```bash
dotnet run -- 2403              # 连接目标（许继模拟器或本库从站）
dotnet run -- 2403 --verbose    # 逐帧打印收发
```

注意：参数必须紧跟 `--` 之后，且用 `dotnet run -- <port>` 形式。
若参数丢失导致连到默认端口，用编译好的 exe 直接跑更稳妥：
`bin/Debug/net8.0/cs103-xuji-interop.exe 2403`

### 多装置 / 多扇区

一台从站可按 CA（`装置地址 << 8 | 扇区`）下挂多台装置，各装置的定值表、当前运行区、
预发暂存、通用分类组、录波数据全部隔离。从站示例当前挂了两台：

| 装置 | CA | 定值 | 通用分类 | 录波 |
|---|---|---|---|---|
| A | `0x0101` | CPU1 区 0~3，各 27 项 | 组 0x0E（7 条）、0x12（3 条） | 2 路 × 50 点 |
| B | `0x0201` | CPU1 区 0~1，各 10 项 | 组 0x0E（1 条） | 无 |

### 故障录波流程（规约 3.7.9）

```
TI=24 TOO=1 选择故障        → TI=26 数据准备好（NOC 路数 / NOE 点数 / INT 间隔）
TI=24 TOO=8 请求某路模拟量  → TI=30 采样数据（NDV ≤ 25 点/帧，分帧）
                            → TI=31 本路结束（TOO=35）
TI=24 TOO=32 扰动结束
```

信息体格式：

| 报文 | 信息体 |
|---|---|
| TI=24 命令（表40/44/50） | `TOO(1) TOV(1) FAN(2) ACC(1)` |
| TI=26 准备好（表41） | `未用(1) TOV(1) FAN(2) NOF(2) NOC(1) NOE(2) INT(2) 时标(4)` |
| TI=30 通道数据（表51） | `未用(1) 未用(1) 类型(1) FAN(2) 名称(1) NDV(1) NFE(2) 采样值(2×NDV)` |
| TI=31 通道结束（表52） | `TOO(1) TOV(1) FAN(2) ACC(1)` |

`NDV ≤ 25`：每帧最多 25 点，超了分帧，`NFE` 是采样点初始序号。

实现位于 `examples/103/cs103-slave-xuji/DisturbanceDevice.cs`。

### 私有 INF 说明

INF=240/241/244/245（读）与 249/250/251（写）**不在规约正文里**，是许继工具实际使用的一组私有 INF。
实测其信息体结构与标准 INF=0 完全一致，只是 INF 字节不同。因此从站按 INF 原样回显即可，
不按 INF 分支解析结构。

`INF=244` 读条目属性时，若请求的组未定义，按 3.7.5 应回 COT=43（读响应无效）。

### 本轮修掉的缺陷

**TI=61 命令的 VSQ 取值错误**（`SettingClient.SendAsync`）

原实现走 `Iec103Client.SendPrivateAsync`，该方法固定按 `SQ=1, N=1` 组 VSQ（即 `0x81`）。
但规约表28 要求带定值项时 VSQ = 「1 个头元素 + N 个定值项」：

| 场景 | 规约 | 修复前 | 修复后 |
|---|---|---|---|
| 调定值 / 执行（无值） | `81H` | `81H` ✓ | `81H` ✓ |
| 单项预发（1 项） | `02H` | `81H` ✗ | `02H` ✓ |
| 整区返校（27 项） | `1CH` | `81H` ✗ | `1CH` ✓ |

修复方式：`SendAsync` 不再走 `SendPrivateAsync`，改为直接构造 `Asdu`，
按有无定值项分别设置 `Sq` / `Count`。

回归测试：`tests/CS103ApduFramingTests.cs` 的 `SettingCommand_VsqMatchesSpecTable`
覆盖无值 / 1 项 / 27 项三种情况。
