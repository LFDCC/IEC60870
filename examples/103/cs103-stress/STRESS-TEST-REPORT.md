# CS103 压力/性能测试报告

工具：`examples/103/cs103-stress`（Release）

拓扑：N 个装置从站（TCP，端口 25500+i）+ N 个主站，一一对应独立链路。
主站循环「召唤 1 级 → 召唤 2 级」，并按间隔下发一般命令与总召唤；
从站后台按 `--spont` 速率主动上送带时标遥信（TI=1）与周期量测（TI=9）。

`--burst` 模式下，从站对**每一次** 1 级召唤都补 `--burst-points` 帧，
形成「一问一答」的自计时闭环，用来量链路 + 解码的吞吐上限。

## 复现

```bash
dotnet run -c Release --project examples/103/cs103-stress -- \
    --devices 100 --duration 20 --quiet

dotnet run -c Release --project examples/103/cs103-stress -- \
    --devices 100 --duration 20 --quiet --burst --burst-points 16
```

## 结果（本机，.NET 8，20s）

| 场景 | 装置数 | 下行 ASDU/s | 1 级 RTT 平均 | 命令 RTT 平均 | 总召唤 RTT 平均 | 超时/错误 | 工作集 |
|---|---|---|---|---|---|---|---|
| 稳态（自发 4 轮/s × 4 帧） | 100 | 2,370 | 1.46 ms | 1.73 ms | 15.7 ms | 0 / 0 | 268 MiB |
| burst（每次召唤回 16 帧） | 100 | **71,302** | 2.31 ms | 1.43 ms | 21.1 ms | 0 / 0 | 272 MiB |
| burst | 30 | 64,895 | 0.50 ms | 0.56 ms | 4.6 ms | 0 / 0 | 249 MiB |

## 解读

- **103 的吞吐上限由「一次召唤能带走多少帧」决定**，不是由窗口决定。
  103 没有 APCI / k-w 窗口，主站只能靠 FCB 交替的 1 级召唤一帧一帧拉；
  客户端 `RequestClass1Async` 内部最多 `4096` 轮（`maxRounds`），
  burst 下每次召唤回 16 帧即可稳定跑满 7 万 ASDU/s。
- **延迟与装置数近似线性**：30 → 100 装置，1 级 RTT 从 0.50 ms 升到 2.31 ms，
  属于单机多连接下的调度开销，不是链路层重传（超时计数为 0）。
- **工作集不随装置数线性增长**：30 与 100 装置都在 250–275 MiB，
  说明每会话的常驻开销主要在共享的调度/缓冲池上。
- **分配速率约 270–340 MiB/s**（GC 0 代 20s 内 26–43 次，1 代 1–4 次，2 代 0–1 次）。
  内存压力来自主站侧物化 API：`RequestClass1Async` 每次把响应
  `Asdu` 物化并放入 `List<Asdu>`。要求极致吞吐时应改用零拷贝的
  `AsduReceived`（`Iec103AsduView`）回调路径，而不是逐帧召唤 + 物化。
- **单个 ~1 s 的 RTT 毛刺**在稳态 100 装置下出现一次（最大值 1034 ms，
  平均值仅 1.46 ms），伴随 gen2 GC；属于首次 JIT / GC 暂停，不是协议问题。

## 与 104 的口径差异

104 的压测（`examples/104/cs104-stress-500`）测的是 500 装置下的
k/w 窗口流水线与 T1/T2/T3；103 是主从式无窗口协议，
两边 ASDU/s 不能直接对比——103 的瓶颈在「召唤轮次 × 每轮帧数」，
104 的瓶颈在窗口大小 k 与 TCP 往返。

## 500 装置复测（v6.1.0，2026-11-07）

```bash
dotnet run -c Release --project examples/103/cs103-stress -- \
    --devices 500 --duration 25 --quiet
```

| 指标 | 数值 |
|---|---|
| 会话（从站/主站建链） | **500 / 500**，失败 0 |
| 建链耗时 | 20.3 s（25 条/s 限速） |
| 下行 ASDU | 295,216（**11,795 /s**） |
| 上行 ASDU | 26,895（1,075 /s） |
| 合计 ASDU 吞吐 | **12,869 /s** |
| 下行字节 | 4.6 MiB（186.9 KiB/s） |
| 1 级召唤 RTT | 平均 8.44 ms，最大 1093.6 ms（n=811,193） |
| 总召唤 RTT | 平均 155.4 ms，最大 1123.2 ms（n=2,395） |
| 命令 RTT | 平均 6.78 ms，最大 25.6 ms（n=24,500） |
| **超时 / 错误** | **0 / 0** |
| 进程工作集 | 323 MiB |
| 托管分配 | 7,594 MiB（303 MiB/s），GC 47/45/1 |
| 原始输出 | `results-500devices-v6.1.0.log` |

结论：**500 装置单机（单进程同时跑 500 从站 + 500 主站）稳定，零超时零错误。**
1 级 RTT 平均 8.44 ms（本run 用了最激进的 `--1级召唤间隔 0ms`，即不限速连轮询，
811k 次召唤把单连接调度开销放大到 8 ms；按实际现场 100~200 ms 的召唤周期会回到毫秒级）。
内存 323 MiB，未见随装置数线性增长。这条结论与 104 的结果相反（见
`examples/104/cs104-stress-500/STRESS-TEST-REPORT.md` 的 v6.1.0 章节），
差别来自链路层实现：103 无 k/w 窗口，不依赖定时器驱动发送。
