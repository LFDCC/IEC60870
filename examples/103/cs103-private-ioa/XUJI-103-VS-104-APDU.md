# 许继 103 规约（PDF）与现版本 104 APCI 承载的差异

对照基准：
- **规约原文**：`许继103通信规约.pdf`（CBZ8000，2005-12-11），全文只描述 RS-232/485 上的 FT1.2
- **现版本**：现场 2403 端口抓包（2026-11-19），报文格式完全按 IEC 60870-5-104，连接仍按 103

结论先行：**规约 PDF 不包含任何网口描述**（全文 grep「网口/以太/TCP/APCI/104」= 0 次），
现版本属于厂商私有实现，需以抓包为准。

## 一、帧层差异

| 项 | 规约 PDF（FT1.2） | 现版本（104 APCI） |
|---|---|---|
| 起始 | `68 L L 68`（长度双写 + 第二启动字符） | `68 L`（单字节长度） |
| 长度语义 | `L = C(1) + A(1) + ASDU` | `L = 控制域(4) + ASDU` |
| 总帧长 | `L + 6` | `2 + L` |
| 控制域 | 1 字节：PRM/FCB/FCV/FC/ACD/DFC | 4 字节：N(S)/N(R) 各 15 位（I 帧） |
| 地址域 | 帧内 1 字节 ADDR | **无**（地址在 ASDU 的 CA 里） |
| 校验和 | 有，`CS = C+A+ASDU mod 256` | **无** |
| 结束符 | `16H` | **无** |
| 固定帧 | `10 C A CS 16`（5 字节） | `68 04 <控制域4B>`（6 字节，S/U 帧） |
| 单字符 | `E5` | 无 |

### 同一「调定值请求」的两种编码

```
FT1.2 : 68 0A 0A 68 53 01 | 3D 81 14 01 B2 64 1F 00 | 5C 16
APDU  : 68 0E 00 00 00 00  | 3D 81 14 00 01 01 B2 64 1F 00
```

两者总长都是 16 字节，但：

- FT1.2 用 `0A 0A` 双写长度 + 第二个 `68` + `01` 地址 + `5C` 校验 + `16` 结束符
- APDU 用 `0E` 单字节长度 + 4 字节控制域，**没有校验和与结束符**

## 二、ASDU 头差异

| 字段 | 规约 PDF | 现版本 | 变化 |
|---|---|---|---|
| TI | 1B | 1B | 同 |
| VSQ | 1B | 1B | 同 |
| COT | **1B** | **2B** | +1B（高字节为源发地址） |
| CA | **1B** | **2B** | +1B（`(装置地址<<8)｜公共地址`） |
| FUN | 1B | 1B | 同 |
| INF | 1B | 1B | 同 |
| **头总长** | **6B** | **8B** | **+2B** |

```
规约: TI(1) VSQ(1) COT(1) CA(1) FUN(1) INF(1)               = 6 字节
现版: TI(1) VSQ(1) COT(2) CA(2) FUN(1) INF(1)               = 8 字节
                        └─┬─┘ └─┬─┘
                      扩宽  扩宽
```

### 偏移对照

| 字段 | 规约偏移 | 现版本偏移 |
|---|---|---|
| TI | 0 | 0 |
| VSQ | 1 | 1 |
| COT | 2 | 2-3 |
| CA | 3 | 4-5 |
| FUN | 4 | **6** |
| INF | 5 | **7** |
| 信息体 | 6 | **8** |

**按规约的 6 字节头解析现版本报文会全盘错位**：CA 读成 0、FUN 读成 1、INF 读成 1，
无法映射到规约表 26 的任何定义。

## 三、COT 位序差异

| 位 | 规约（103） | 现版本（104 位序） |
|---|---|---|
| bit7 | **P/N**（否定） | **T**（试验） |
| bit6 | 原因高 1 位 | **P/N**（否定） |
| bit5-0 | 原因低 6 位 | 原因 |

若沿用 103 的掩码解析现版本报文，装置回否定确认（104 编码 `0x55`）时会被解成
「原因=85、非否定」，**把拒绝当成成功**。

## 四、CA 语义差异

| 项 | 规约 PDF | 现版本 |
|---|---|---|
| 宽度 | 1 字节 | 2 字节 |
| 语义 | 单元公共地址 = 站地址（即装置地址）；多 CPU 装置时可作 CPU 分地址；255 = 广播 | `(装置地址 << 8) ｜ 公共地址(扇区)` |
| 现场值 | — | `0x0101` → 扇区=1、装置地址=1 |

「装置地址」指保护装置自身的编号，与 103 串口里的链路地址不是同一层概念。

## 五、传输语义差异

| 项 | 规约 PDF（103 非平衡） | 现版本（按 104 实现） |
|---|---|---|
| 主从关系 | 非平衡，主站轮询 | 平衡，从站可主动发送 |
| 数据获取 | 装置入 1/2 级队列，主站 `C_PL1/C_PL2` 召唤 | **装置收到即回 I 帧，无召唤环节** |
| 链路确认 | `M_CON_NA_3` 固定帧 ACK | 无独立确认帧 |
| 主站收数 | `RequestClass1Async` 拉取 | `AsduReceived` 事件订阅 |
| 连接管理 | 复位链路 / FCB 翻转 / 1/2 级队列 | **不做** STARTDT 握手、不维护 k-w 窗口 |

> 现场工程师确认：「只有报文传输完全采用 104，连接依然是 103。」
> 因此 S/U 帧虽在格式上存在，但不参与通信。

## 六、报文实例差异

### 调定值请求

| | 字节 |
|---|---|
| 规约 FT1.2 | `68 0A 0A 68 53 01 3D 81 14 01 B2 64 1F 00 5C 16` |
| 现场 APDU | `68 0E 00 00 00 00 3D 81 14 00 01 01 B2 64 1F 00` |

### 调定值应答（27 项定值）

| | 结构 |
|---|---|
| 规约 | `68 L L 68 C A` + 6B 头 + 83B 信息体 + `CS 16`，信息体 = `1F 00` + 27×3 |
| 现场 | `68 5F` + 4B 控制域 + 8B 头 + 83B 信息体，无 CS/16H |

**信息体部分两者完全一致**（CPU/区 + 序号 + 值/属性三元组），差异只在帧壳与 ASDU 头。

## 七、协议标准符合性

| 层 | 是否符合标准 |
|---|---|
| 帧结构 | ✅ 遵循 IEC 60870-5-104 的 APCI |
| ASDU 字段（TI/VSQ/COT/ORG/CA） | ✅ 各字段分别符合 104 |
| ASDU 语义（FUN/INF、TI=61、COT 表 B） | ✅ 遵循 IEC 60870-5-103 |
| **「CA(2B) 后直接跟 FUN/INF」的组合** | ❌ **不在任何 IEC 标准中** |

DL/T 667-1999 正文 §4.1 原文：

> 此配套标准的应用层**未采用**明确的应用规约控制信息(APCI)，它暗含在应用服务
> 数据单元的数据单元标识符内以及所采用的链路服务类型中。

因此对外表述应为「许继 103 网口承载」，**不能表述为「实现了 IEC 104 标准」**。
